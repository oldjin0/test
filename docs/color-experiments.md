# 컬러 실험 기록 (2026-10)

흑백 만화를 "완전 컬러"로 만들기 위해 시험한 방법과 결과. 정답이 있는 자료(표지 3장,
애니메이션 그림 4장)와 실제 흑백 페이지 12쪽(나루토, 원피스, 안녕 꼬리 달린 녀석)으로 시험했다.
이미지는 저작권 때문에 저장소에 넣지 않았다. 스크립트는 `tools/color_experiments/`
(경로는 시험 때의 `/tmp/claude-0/exp` 기준이다).

색 오차 = 정답과의 (Cb, Cr) 평균 거리(낮을수록 좋음). 흑백 그대로 두면 표지에서 41(나루토),
21(원피스), 21(안녕)이다.

| 방법 | 결과 |
|---|---|
| 지금 앱의 모델(manga-colorization-v2, 448) | 흑백으로 두는 것과 정확도가 비슷하다(45 / 19 / 23). 선화 페이지에서는 한 가지 색조(올리브/크림)만 낸다. 순백을 낮춰 입력해도 같다. |
| 앱의 표 학습(BookColorMap) | 모델이 색을 주지 않은 영역에는 적용되지 않는다. 변화가 작다. |
| 영역 형태 은행(FormBank, build-66) | 형태가 비슷한 영역을 구별하지 못해 페이지 전체가 주황 한 톤이 된다. 코드의 `useFormBank = false`로 꺼 두었다. |
| 표지 팔레트를 영역 톤에 맞춰 칠하기 | 오차 개선이 작고 책에 따라 오히려 나빠진다(37 / 15 / 23). |
| DDColor (456MB ONNX) | 애니메이션 그림에서는 선명하다. 만화 페이지에서는 선과 톤 위에 얼룩이 생기고, 흰 영역을 낮추면 페이지가 노랗게 뒤덮인다. |
| DINOv2 의미 매칭 (참고 이미지의 같은 부위 색 가져오기) | 원피스 애니메이션 쌍에서 오차가 가장 낮았다(34, 26). 만화 페이지에서도 손이 살색, 머리가 갈색 등 자연스러웠으나 옅다. 색을 키우면 엉뚱한 곳(얼굴, 말풍선)이 물든다. 큰 모델(base)과 엄격한 기준으로 바꾸면 거의 칠하지 않는다. |
| 매칭 + DDColor 합성 | 수치와 눈 모두 나아지지 않았다. |
| 참고 이미지 + 선화 제어 확산 모델(ControlNet lineart anime + IP-Adapter, CPU 한 장 약 4분) | 색은 선명하나 컷마다 내용을 새로 그려 색이 따로 놀고 무지개처럼 번진다. 말풍선과 여백이 물든다. 참고 이미지의 인물 색을 거의 따르지 않았다. 억지스럽다는 평가. |
| 작업지시서 파이프라인(`run_pipeline.py`): 표지 팔레트(k-means) → 스크린톤 제거 → 말풍선/여백 흰색 고정 → 영역 중심에 밝기별 팔레트 색 힌트(반지름 8) → 5채널 colorizer | 힌트를 줘도 모델이 거의 따르지 않아 색이 사실상 나오지 않는다(원피스: 회색에 크림 종이색). 지금 앱 방식보다 약하다. 영역 칠하기(fill 0.7)를 더해도 가장자리에 옅은 노랑만 생긴다. |

## 결론

공개된 모델과 영역/매칭 규칙만으로는, 선화 만화 페이지에서 "선명하고 틀리지 않는" 색을
동시에 얻지 못했다. 정밀도(틀린 색 없음)와 재현율(여러 곳이 칠해짐)이 맞교환이다.

## 남은 길

1. 만화/선화로 학습된 채색 모델이 필요하다. 컬러 일러스트(표지, 애니메이션 그림,
   책의 컬러 페이지)에서 선화와 톤을 합성해 짝(흑백 ↔ 컬러)을 만들고, 참고 색 힌트를
   받는 모델(현재 모델은 이미 힌트 5채널 입력이 있다)을 미세 조정한다. GPU가 필요하다.
2. 참고 이미지를 받는 확산 모델(MangaNinja 등)은 GPU에서 한 장에 수십 초 이상 걸려
   휴대폰 실시간에는 맞지 않는다.
